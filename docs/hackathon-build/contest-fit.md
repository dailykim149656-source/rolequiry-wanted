# 원티드 AI Championship 2026 적합성 점검

점검일: 2026-09-04
공식 근거: [대회 랜딩](https://event.wanted.co.kr/ai-championship/2026), [랜딩 원문](https://static.wanted.co.kr/ai-championship/2026/landing.html), [참가약관](https://help.wanted.co.kr/hc/ko/articles/61147702526617)
제품 근거: [구현안](wanted-edition-source.md), 현재 `rolequiry-wanted` 코드

## 결론

구현안은 원티드 대회에 제출 가능한 방향이다. 자유 주제, 실제 작동 서비스, AI 활용 설명, 로그인 없는 배포 링크라는 예선 조건과 맞는다. 지금 클론된 코드는 WebMCP Challenge용이라 그대로 내면 예선에서 약하다. 구현안의 P0를 지켜야 원티드 심사·투표 화면에 맞는다.

## 잘 맞는 지점
1. 문제는 원티드와 회사 쪽 모두에 읽힌다. 맞지 않는 채용을 입사 전에 발견하는 일은 지원자 self-selection이자 회사의 채용 비용 절감이다.
2. AI가 점수를 내지 않고 claim·evidence·question을 가른다. 예선 'AI 활용 적절성'과 본선 '기술력'을 설명하기 좋다. Luna가 추출/조사, 코드가 ranking을 소유한다는 경계가 분명하다.
3. 로그인 없는 배포 링크와 샘플 데모는 2주 투표에 필요하다. 구현안이 이 점을 이미 전제로 둔다.
4. Wanted-first, not Wanted-only는 대회 내러티브에 쓰이되 원티드만 되는 폐쇄 툴로 보이지 않는다.
5. 제외 목록이 예선에 맞다. 계정, 결제, 자소서, 자동지원, fit score, 대규모 리뷰 크롤링은 시간·약관·차별화 모두에서 빼는 편이 맞다.
6. 기존작 재사용은 공식 FAQ가 허용한다. WebMCP 코어를 남기고 hosted intake를 얹는 구성은 약관상 막히지 않는다.

## 지금 코드가 막히는 지점

1. 첫 화면이 없다. `app/page.tsx`가 `/case`로 redirect한다. 심사자와 투표자는 WebMCP 상태부터 본다.
2. 공고 URL을 붙여넣는 경로가 없다. claim import는 agent tool에 달려 있다.
3. 원티드/ATS URL은 회사 도메인이 아니다. 지금 `sourceUrl` 하나로 employer official을 판단하면 wanted.co.kr 공고에서 authority가 깨진다. 구현안의 `jobPostingUrl` / `companyWebsite` / `employerDomain` 분리가 필수다.
4. 제품 안에 추출·리서치·verifier가 없다. 현재는 연결된 agent가 조사하고 Rolequiry는 기록만 한다. 원티드 제출물은 링크만 열어도 동작해야 한다.
5. 메인 UX가 영어이고 WebMCP diagnostics가 노출된다. 예선 투표 화면과 안 맞는다.
6. 제출서에 쓸 AI 툴 이름이 코드에 없다. 구현안의 Luna/Terra를 실제 호출과 제출 문구에 맞춰야 한다.

## 예선 채점 렌즈
- 기획력: 입사 전에 이 역할이 나와 맞는지 확인한다는 한 문장이 랜딩에서 끝나야 한다. 회사 저격처럼 읽히면 안 된다.
- 실현 가능성: 샘플 데모가 외부 API 없이 끝까지 가고, 실제 원티드 URL은 fallback까지 보여야 한다.
- 확장성: 한 JD를 깊게 본 뒤 여러 role 비교로 가는 로드맵만 말하고, 지금은 구현하지 않는다.
- AI 활용 적절성: 추출은 quote 검증, 조사는 한 claim, 판정은 researcher와 분리, ranking은 코드. 이 네 경계가 제출 문구의 핵심이다.

## 제출 전 가드

- 배포 링크는 로그인 없이 연다.
- 제출 폼에 문제, AI 활용 방식, 사용한 AI 툴을 적는다.
- 과제에 이력서·주민번호·회사 기밀을 넣지 않는다.
- 원티드 로고/브랜드를 공식 후원처럼 쓰지 않는다. 입력 예시로만 쓴다.
- 심사 기간 동안 샘플 데모가 살아 있는지 매일 확인한다.
